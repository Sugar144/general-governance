# Upgrade: `0.1.0-rc.1` -> `0.1.0-rc.2`

## Reason

`0.1.0-rc.1` could pass official consumer validation without a required L1
configuration instance and carried a HugePlanning-specific material-prompt
identifier in reusable L0 semantics. `0.1.0-rc.2` corrects both prospectively.

## Compatibility transition

- release: `0.1.0-rc.1` -> `0.1.0-rc.2`
- framework contract: `1.0.0` -> `2.0.0`
- current consumer-lock schema: `1.0.0` -> `2.0.0`
- consumer-configuration schema: absent -> `1.0.0`
- prior lock validation for controlled upgrade: schema `1.0.0` remains accepted
  only as `--previous-lock`

The new lock adds:

```json
"consumer": {
  "configuration_path": "<consumer-owned relative YAML path>"
}
```

and compatibility becomes:

```json
{
  "framework_contract": "2.0.0",
  "consumer_lock_schema": "2.0.0",
  "consumer_configuration_schema": "1.0.0"
}
```

## Required configuration values

The adopter-owned YAML instance must resolve all of:

- `configuration.correction_example.base_run_id`
- `configuration.correction_example.first_correction_id`
- `configuration.paths.formal_run_prompt_snapshots`
- `configuration.paths.learning_readme`
- `configuration.identity_allocator.namespace`
- `configuration.identity_allocator.state_path`
- `configuration.identity_allocator.ledger_path`
- `configuration.prompt_identity.namespace`
- `configuration.prompt_identity.sequence_width`

No required value may contain an unresolved `{{...}}` placeholder.

## HugePlanning adopter #1

HugePlanning already owns
`governance/adopters/hugeplanning/configuration.yaml` and already supplies the
seven pre-existing values. Its controlled upgrade therefore requires only:

```yaml
configuration:
  prompt_identity:
    namespace: HP-PROMPT
    sequence_width: 3
```

plus a schema-2.0 `framework-lock.json` whose
`consumer.configuration_path` is
`governance/adopters/hugeplanning/configuration.yaml`, and an upgrade record
from its exact `0.1.0-rc.1` lock to the new immutable release identity.

This preserves HugePlanning's existing project semantics; it does not make the
`HP-PROMPT` namespace universal.

## Dopis adopter #2

GOV-GEN does not choose a Dopis project namespace. Dopis must supply one
explicitly under Dopis authority, together with the other required L1 values,
in an adopter-owned YAML file and identify that file in the schema-2.0 lock.
The validator must pass before the adopter is considered conformant.

No Dopis file is modified by this framework correction.

## Validation command

```text
python3 tools/validate_consumer.py   --consumer <consumer-repository>   --framework <exact-0.1.0-rc.2-checkout>   --previous-lock <exact-old-framework-lock.json>
```

A successful result proves framework conformance only; it does not authorize
project implementation, merge, release, or product changes.
